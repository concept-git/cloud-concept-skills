# 从 skill／recipe 提取

## 按场景读取依赖

1. 读入口的触发条件、适用边界和路由。先选当前场景的工作流，再沿它的链接读判断依据、命令定义和相关脚本；不要把整个仓库拼进上下文。
2. 为相关依赖登记“已读／不可读／仅列链接”。核对来源链接是相对文件还是相对 skill 根目录；按来源目录结构确认实际目标，记录修正的解析基准。找不到时保留缺口，不猜另一文件作为替代。远程 URL 未取得正文时，仅记录链接和缺口，不根据标题扩写处理方法；已有足够本地证据的部分可以继续。
3. 脚本先静态检查参数、目标选择、执行通道、外部调用、写入行为、错误处理及输出字段。混合脚本按相关子段登记“目标／输入／行为／输出／错误路径”，分别提取查询与变更；不得将整脚本描述为只读。只提取已检查部分；注释中的安全声明与代码行为冲突时记录冲突。
4. 材料足以支撑本次场景的每个关键分支，或剩余缺口已明确限制产物范围时，停止扩展读取。输出说明这次覆盖的场景，不将入口文件已读等同于整个 skill 已分析。

## 提取单位

对拟收录步骤记录：适用条件、所需输入、要获得的观测、判断条件、下一步或退出条件、操作性质、原文位置。保持“如果 X，则检查 Y”的关系，避免只导出命令清单。

- 路由表提供问题入口，不证明根因；工具返回的状态与业务健康之间仍可能有证据缺口。
- 脚本输出里的失败占位文字、截断范围和可选工具缺失也属于解释条件。没有输出不直接等于没有异常。
- 故障系统、诊断机和离线挂载盘分开建模；操作路径、服务状态或注册表属于哪个对象必须明确。
- 作者的工具偏好、遥测标记和评测格式通常留在来源记录；影响技术正确性的版本、参数约束与权限前提随步骤保留。

## 平台转换

默认保留来源平台和产品。用户要求华为云等目标平台时，对每个云操作记录：来源能力、目标能力、目标契约位置、核对状态。

- 目标契约存在且语义与输入输出相符：引用该契约，参数依赖仍按目标环境解析。
- 只有通用 OS／协议知识：保留系统版本和命令适用条件；不能由此推断云控制面已适配。
- 契约缺失、语义不同或无法核实：将该步骤写为待适配检查目标，记录缺口。不得机械替换 `az`／`aliyun` 为 `hcloud`。

为新写文章计算其落盘位置相对目标契约的正确链接；将来移入 `recipes/kcs` 时外层流程需要重算链接并检查。没有目标契约时采用无链接的检查目标描述，追溯记录给出来源定位。

## 常见需要降级的内容

| 来源表述 | 提炼处理 |
| --- | --- |
| 查询为空，因此实例不存在／环境正常 | 保留账号、区域、权限和过滤条件等可能性；若来源也无确认依据，记录证据缺口 |
| 实例不可访问，因此直接按 GuestOS 问题处理 | 可整理有限证据的后续检查，原因与故障边界仍为未知 |
| 大部分连接问题由某配置造成 | 有可核实统计及适用范围才保留数字；否则只提取检查方向，不凭比例决定原因 |
| 一组 quick commands 同时含检查与重置 | 分离采集和修复；修复保留触发证据、影响及来源提供的验证／恢复条件 |
| 同一功能不同版本使用不同参数 | 按已知版本分支；未知版本记录待核验，不拼成混合命令 |
