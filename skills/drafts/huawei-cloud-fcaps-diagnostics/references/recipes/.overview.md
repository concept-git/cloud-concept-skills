# recipes

本目录提供华为云 FCAPS 诊断技能的 KCS 场景文章草稿，帮助把用户现象转成有顺序的证据检查，覆盖启动、登录、网络、存储、性能、崩溃、配置、安全和恢复。文章依据目标云资源、Linux／Windows 主机或可选 Kubernetes 环境选择命令与映射，强调确认失败阶段、保留缺口并按原症状验证处置效果。它与命令契约库共同使用，适合需要排查步骤、而非仅查询单项事实时选读。

  - 响应变慢或负载升高 → [性能](kcs/performance.md)，业务与资源指标对齐。
  - 整机重启、服务退出或容器重建 → [崩溃](kcs/crash.md)，事件时间线。

## 详细说明

### [kcs](kcs/)

文章均按 Issue、Environment、Resolution、Cause 组织：问题与适用条件之后，用编号步骤链接契约，原因区分已知、未知或不适用。按现象选一篇，命令、工具、Helper 和文档只在当前步骤需要时补读。

### [启动](kcs/boot.md)

先区分平台未完成启动、OS 启动异常和仅登录失败，再关联 ECS 状态、已有 Job、控制台日志与可用的系统事件。日志缺失记为缺口；不为补证据重启或重装。验证分别关注实例、系统和目标业务。

### [登录](kcs/login.md)

按客户端错误、来源、目的和身份选路径；未启动转启动文章，超时或拒绝转网络文章。经已有通道核对服务、连接和认证日志，端口连通不等于登录成功。

### [网络](kcs/network.md)

按协议、端口、方向和时间定位边界，由 ECS 网卡映射端口、子网及必要的 EIP，再检查路径上的网络对象与主机防火墙。容器场景补查端点和 NetworkPolicy；探测结果不能单独证明业务路径健康，抓包另核范围与开销。

### [存储](kcs/storage.md)

逐层关联 EVS、整盘、分区、文件系统与目标路径，Windows 使用磁盘／分区／卷关联，PVC 按 volumeName 继续查 PV。Linux 空间与 inode 分别检查，df／du 差异补查打开的已删除文件。扩容、格式化、卸载和修复不由查询流程授权。

### [性能](kcs/performance.md)

把延迟、吞吐和错误变化与同资源、同时间窗的 CES、主机有限采样或容器指标对齐，并选可比正常时段。Linux I/O 需设备映射，Windows 先发现计数器，Kubernetes 依赖 metrics API；缺指标不能记为零，高利用率不能单独证明瓶颈。

### [崩溃](kcs/crash.md)

区分整机、服务和容器的状态变化，关联 CTS、计划事件、系统日志与前一容器日志。Pod 名称可重用，须保留 UID；当前启动的内核日志不能覆盖上次启动。按时间排序证据，不主动再次重启或触发转储来重现问题。

### [配置](kcs/configuration.md)

期望值来自变更要求或基线，依次核对对象、提交、运行时加载和持久化。服务启用与运行分开，Linux 防火墙运行时规则与 Windows 有效策略分别检查；未覆盖的机制另读产品依据。

### [安全](kcs/security.md)

先分清权限拒绝和疑似异常访问，再核对 IAM／Kubernetes 身份、授权范围、已有告警、审计和主机记录。HSS 只读已有状态使用 `refresh=false`，不自动启动扫描。隔离、阻断、查杀或重置凭据另需相应授权；单条告警不足以确认入侵。

### [恢复](kcs/recovery.md)

先确认恢复对象、依赖、可接受中断和数据回退范围，再核对资源与备份对象、时间及状态，形成步骤、影响、保护措施、停止条件和验收方案。本文尚未完成恢复演练；备份清单不证明可恢复，任务成功也须继续核验数据、挂载和业务。Cause 标为不适用，不预设故障根因。
